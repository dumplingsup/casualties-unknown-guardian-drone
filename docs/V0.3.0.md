# Guardian Drone 0.3.0 — 战斗／治疗优先级

日期：2026-11-19。来源：Nexus mod 985 的玩家反馈（Ondra52011，2026-11-19）：无人机“完全无视敌人，一受伤就开始治疗”，并建议把优先键做成可切换到“防御优先”的开关，屏幕内出现威胁时保持防御，画面清空后再治疗。外观皮肤按用户决定不在本版实现。

## 1. 复现

在隔离副本 `furry/.local/cu-test/drone-game` 中先用冻结的 0.2.1 DLL 复现：

- 生成一只静态 `wallbiter`，主角肢体注入出血 8。
- 0.2.1 的 `healLatch` 立即置位，`target` 被清空，模式从巡航变为 `approach-medical`／`healing`，`shots` 不再增加。
- 出血降到 0.15 以下后回到巡航，期间不处理仍然存在的敌人。

这与 0.2.0 验收记录中的设计一致，不是 0.2.1 的回归。

原因在 `DroneController.Step`：

- 总出血 ≥ 1 即置 `healLatch`，直到 < 0.15 才解除。
- 锁存期间直接 `target = null`，且开火条件要求 `!healLatch`。
- F8 只是 12 秒的强制治疗窗口，同样会清空目标。

“无视实体”还有第二个原因：敌人白名单只有 6 类。反编译确认 `CrystalEnemy` 会攻击玩家、拉威胁音乐，但其碰撞体在 `Descriptor` 层，原扫描层不包含它；`GuardScript` 的 prefab 带 `indestructible=true`，而旧的 `IsEnemy` 把该标志当作“不可选中”，导致守卫也被忽略。

## 2. 改动

### 自动（默认）

- 目标选择与治疗锁存解耦：`healLatch` 不再清空 `target`。
- 有可交战目标时 `CombatHold=true`，暂停非急救治疗并继续射击；目标消失后经过 0.75 秒迟滞再恢复治疗。
- 总出血达到 `CriticalBleed`（默认 10）时，自动模式仍急救，避免战斗中失血死亡。
- 治疗中如果目标出现，立即关闭光束、清 `healLatch` 并转向战斗。

### 防御优先

- 以屏幕为界：扫描主角附近受支持敌对实体，要求相机可见（含 1.5 格边缘余量）和视线检查。
- 屏幕内有威胁时保持防御并暂停治疗；画面清空并稳定 1 秒后恢复治疗；治疗中威胁重新出现会立即停止治疗。
- 屏幕威胁扫描半径上限 30 世界单位；默认相机很大，超出 30 格的目标不参与防御保持。开火距离仍是各敌人原来的 `Engaging` 距离。
- 迟滞 1 秒，避免威胁在屏幕边缘来回时频繁切换。

### 医疗优先

- 保留“先治疗”的语义，但改为持续姿态，直到 F8 再切走。
- 明确选择医疗优先时，威胁在场也会继续治疗。

### F8 与状态

- F8 从一次性 12 秒请求改为三态循环：**自动 → 防御优先 → 医疗优先 → 自动**。
- 左上角状态框显示“护航／停火 · 自动／防御／医疗”，第二行显示当前动作；治疗被威胁打断时显示“暂停治疗”。
- 优先级通过 CUCoreLib 随角色保存。`schemaVersion` 保持 1，新增可选 `priority` 字段；0.2.1 旧存档没有该字段时按自动处理。0.3.0 存档被 0.2.1 读取时旧版会忽略该字段，不会损坏存档。
- 新增配置 `Support/CriticalBleed`，默认 10，范围 1–40。

### 敌人识别

- `CrystalEnemy` 加入白名单，扫描层加入 `Descriptor`。
- `GuardScript`、`TurretScript`、`CeilingTurret` 等脚本敌人自带死亡路径，`indestructible` 只是绕过通用建筑销毁，不再阻止选中。
- `TraderScript` 仅在 `hostile` 为真时视为敌人。
- 保留 `cantHit`、`health <= 0` 和视线检查；不把所有 `BuildingEntity`、动物或陷阱当成敌人。

## 3. 实测

隔离副本：`D:\testGround\furry\.local\cu-test\drone-game`，真实游戏进程，BepInEx 5.4.23.6、CUCoreLib 1.1、QoL Unknown 7 v1.1.4。所有命令通过仅测试用的 DroneProbe 文件桥发送；游戏数据目录是独立的 `drone-userdata`，没有读写正式用户目录。

| 场景 | 结果 | 证据 |
|---|---|---|
| 启动后控制器 1、无人机 1 | PASS | `v030-final1` |
| 自动：有目标时注入出血 8 | PASS | 模式保持巡逻／战斗，`combatHold=true`，`treatmentHeld=true`，`shots` 持续增加 |
| 自动：清掉敌人后恢复治疗 | PASS | 模式转为 `approach-medical`／`healing`，`healingSeconds` 增加 |
| 防御：屏幕内 20 格威胁 + 出血 8 | PASS | `threatOnScreen=true`、`combatHold=true`，`healingSeconds` 始终为 0 |
| 防御：威胁移出屏幕 | PASS | 约 1 秒后恢复治疗 |
| 防御：威胁重新进入屏幕 | PASS | 光束停止，`healing=false` |
| 医疗：威胁在场 + 出血 8 | PASS | 持续 `healing`，`combatHold=false` |
| 自动：出血 12 超过临界值 | PASS | 出现 `approach-medical`，`combatHold=false`，出血降到 10 以下后恢复战斗 |
| `CrystalEnemy` 识别 | PASS | `recognized=true`，`target=crystalenemy`，`Descriptor` 层碰撞体 |
| `GuardScript` 识别 | PASS | `recognized=true`，`indestructible=true` 仍可选中 |
| `TurretScript` 识别 | PASS | `recognized=true` |
| 主角挡在弹道 | PASS | `friendlyHits` 不增加，模式为 blocked／reposition 等 |
| 真实 F8 三态循环 | PASS | 可见游戏窗口投递 F8 窗口消息，状态依次 1／2／0；同时保存 HUD 截图 |

| Save Anywhere／QoL 回归 | NOT_RUN | 本版未重新组合这两个模组；0.2.1 的回归记录仍有效，0.3.0 只新增可选字段 |

## 5. 仍未覆盖

- `TraderScript` 敌对路径已按 `hostile` 条件接入，但没有在游戏内生成敌对商人做实测。
- 屏幕威胁上限 30 世界单位；默认相机横向可视范围更大，超出 30 格的目标不会暂停治疗。开火距离仍按各敌人类型。
- 多人、守卫／炮塔以外的未列出敌人、其他游戏版本、长局性能没有重新验收。
- 真实 F8 用窗口消息投递，不是物理键盘；输入路径与玩家按键相同（`Input.GetKeyDown`），但物理键盘手感仍需玩家侧确认。
- 状态框仍可能与左上角原版物品标签重叠；最终上架复核使用静音，音效听感未重新验收。
