# Guardian Drone 0.1.0 可玩性复核与下一版方案

日期：2026-11-15。**本文件是源码与现有实测证据的复核，方案尚未实现。0.1.0 的可靠同伴体验不通过。** 本轮没有修改玩法、重新启动游戏或替换已发布的 ZIP。

## 哪些已证实，哪些仍是风险

本地复核材料来自工具工作区的 `runs/guardian-play-20261115`：`playability.json`、`status.json`、`telemetry.jsonl`、截图，以及独立测试探针的 fixture 实现。这些原始材料留在本地，不随公开源码分发。

| 观察 | 复核结论 |
|---|---|
| 读档后一个控制器、一台无人机，停火状态恢复；约 9 格巡航，传送后跟回 | 这些基础机制已成立，不应因战斗失败否认；也不足以证明可靠同伴体验 |
| 同局累计 20 枪、20 次身体命中、敌人仍 1000 血；结束时主角血量 96.70252 | 开火前不检查弹道，这是已证实的缺陷。前 8 发来自 `crossfire`：探针把无人机、主角、敌人排成一条线。后 12 发在开阔场地，敌人只放在主角侧方约 8 格，无人机自己飞到主角另一侧后仍全部打中主角、没有打中敌人。两种几何都不能换成普通战斗的误伤率 |
| 洞里向一条肢体注入出血 8 | 注入后约 5 秒，治疗时间从 1.99 增到 2.40，修复量从 13.28 增到 17.31，但这条采样肢体只从 8 降到 7.88，增加的修复多半不在这条伤口上。随后两次取样治疗时间都停在 2.4、修复量都停在 17.31，距离 3.17，治疗标志关闭，出血再降约 0.03。原版肢体每秒大约按 0.025 乘凝血系数自行下降。这段微降不能记成无人机疗效，首先要修落点和可达性 |
| 开阔近处能把外伤出血降为 0 | 治疗机制可用；落点、可达性与进入治疗条件存在缺陷，不能仅提高修复数值 |
| 正常画面难辨识外形 | 源像素与屏幕可读性是两项验收。贴图已经使用 Point 采样，单改过滤方式不能解决问题；巡航代码没有镜头边界约束 |
| 无敌且会主动选择目标 | 源码支持；测试敌人禁用了 SpiderHandler AI，因此该轮不能证明真实敌人是否会对它或主人转移仇恨 |
| F6/F7/F8 与多人 | 真实按键和多人仍为 NOT_RUN；静态搜索没发现直接写出的原版 F6/F7/F8，不能据此认定绑定无冲突 |

历史记录中的逻辑 smoke PASS 继续保留，但总体验结论改为 **GAMEPLAY（可靠性／可玩性）FAIL**。旧记录见 [V0.1.0.md](V0.1.0.md)。

## 1. 先修开火决策，保留偶发误伤

根因在 [DroneController.cs](../src/GuardianDrone/DroneController.cs)：`CanSeeThreat` 只检查 Ground，不检查主角身体；预检查从无人机中心出发，真正弹丸却从旋转后的枪口发出。[DroneProjectile.cs](../src/GuardianDrone/DroneProjectile.cs) 会命中沿途第一个实体，这部分实际碰撞与“允许误伤”的要求一致。

下一版应在枪口完成瞄准后，用实际枪口、弹丸半径和散布范围检查射击走廊。主角或旁人已经挡住时暂停开火，横移／升降寻找可达射位；没有合适位置就显示“射线受阻”。地形、触发器、碰撞层及查询溢出处理与实际弹丸一致，避免预检查说安全、弹丸却先撞到另一物体。

已发射的子弹继续碰撞主角：玩家在开枪后冲进弹道，仍可能误伤。不要改为身体免疫，也不要增大散布掩盖挡枪。身体受击落到头部与几何位置、最近肢体选择有关，源码没有主动锁定主人头部的逻辑。

同步增加可见曳光、枪口闪光和可辨认的开火／命中声音。提示时长与弹速在正常游戏画面中调整，不能承诺只加一道短线就让玩家来得及躲。

## 2. 治疗、战斗与脱困一起修

当前医疗落点只是“伤口侧上方”，候选点只要求没有地形碰撞，没有同时满足可达、治疗距离和光束无遮挡。治疗判定从机体中心计算，光束却从工具发出，也有起点不一致的问题。

医疗候选必须满足：实际工具端到伤口在治疗范围内并留出移动余量、医疗射线通畅、路径可达、机体有净空。按距离和路径代价选点，不能找到一个空位就算完成。到位后稳定悬停；伤口移动或射线阻断时重新选点。日志区分“正在靠近”和“实际修复”，绿色治疗光只在确实产生疗效时亮。

行为分成急救、战斗、普通修复与巡航。急救进入和结束采用不同阈值，并保留一次治疗过程，避免出血刚低于 1 就重新开枪。非紧急的轻微皮肤缺损不再触发持续贴脸：可等待安全间隙、显著损伤或 F8 明确请求；普通修复完成后回巡航。严重程度应考虑全身出血，不只看某一块皮肤是否满值。具体阈值先作为可调参数，再由实测确定。

保留本版医疗边界：止外伤出血、修复仍存在的皮肤和肌肉；不自动补血、不再生断肢、不处理骨折、内伤、感染等。纳米治疗的表现可用短距离定向光束与伤口粒子，但必须明确“外伤处理”，避免绿色光让玩家误以为所有伤势已治愈。不能用全身回血掩盖自己反复造成的伤害。

脱困属于同一批修复：[DroneController.cs](../src/GuardianDrone/DroneController.cs) 的超时恢复在 `Move` 内；`FindHover` 完全失败时不调用 `Move`，持续增加卡住时间也触发不了恢复。恢复检查必须在目标点查找之外执行。无路时停止开火／治疗，尝试有界重新选点；仍无空位则收纳等待，主人移动到有净空的位置后再部署。不得把瞬移落点直接设在墙内。

## 3. 同时提供可见状态、画面内巡航与外形

将“自动防卫／停火”这个持久模式和“巡航／调整射位／靠近急救／治疗中／路径受阻／等待部署”这个当前活动分开显示。部署后在屏幕固定位置用图标加短文字显示，不只靠眼睛变色；读档、切换模式、控制器离身时有一次明确提示。停火继续保留自动医疗。

巡航保持远距意图：开阔处仍优先约 6–9 格，镜头可见区域、地形净空和主人周围禁入区域共同约束候选点；低洞允许较低、较近的侧方护航。不能先强制高空绕圈，再因找不到落点回退到脸旁。不可同时满足可见与净空时提供离屏／受阻提示，不强行穿墙来维持画面内位置。

像素迭代先强化四个桨盘、机身中心和下挂工具的轮廓，减少细碎高光，增加明暗描边；然后按正常镜头的实际占屏尺寸调整比例。同步核对导航净空：当前贴图宽约 4 世界单位，寻路半径仅 0.55，继续放大外形会加剧视觉穿墙。桨叶动画、灯光和轮廓都要在正常亮度、背景与游戏后处理下检查，不能仅验收放大的源图。

增加低音量旋翼、部署／收回和治疗声音，提供音量控制，避免持续循环盖住原版威胁音。控制器图标单独重画为能在背包格子辨认的剪影。

控制器离身仍收回无人机，但显示原因。免费初版提供明确的零成本补领入口，按当前角色是否已有控制器去重；不在每帧自动赠送，也不把短暂离开背包当成新角色。保留现有物品 ID 和存档字段。

## 4. 最后扩敌人，默认保护主人

当前只认识 SpiderHandler、CaveTicks、LaserDroneScript，28 格扫描不判断是否已经交战。扩大类型名单之前先完成安全射击和状态决策，否则只是让它对更多目标错误开火。

建议默认保护主人：优先已攻击／正在攻击主人或主人正在交战的可确认敌人，不仅因远处类型在名单中就先开战。每类敌人的敌对性、休眠状态、原生受击入口与仇恨响应都要逐类核对；未知／中立对象不自动扩大为敌人。识别不了敌意时保守停火，显示无可确认目标。主动清场可以作为后续独立模式，避免初版增加多套操作。

守卫、炮塔和其他威胁按原生组件与敌意机制逐类接入，实测实际伤害与仇恨；不把所有 BuildingEntity 或 Body 当成敌人。继续保持免费、无敌的原型设定，不在这一轮加入资源经济、损坏和升级系统。真实 AI 参与的战斗必须另测，不能用静止探针敌人代替。

## 建议的下一版验收门槛（尚未执行）

| 场景 | 必须观察到的行为 |
|---|---|
| 主角静止挡在枪口和敌人之间 | 无开火、无自伤；可移动到可达安全射位，或明确提示受阻 |
| 射线畅通；开枪后玩家再横穿 | 敌人真实掉血；后发的横穿仍允许被已发射弹丸击中 |
| 外伤出血 8，开阔与低顶洞穴分别测试 | 在可达 fixture 中目标 3 秒内到达治疗位；保持 5 秒有效医疗，治疗计时持续增长、出血明显下降，不把自然凝血计入成绩 |
| 轻微擦伤与战斗交替 | 轻伤不持续贴脸；急救不中途因单帧跨阈值恢复射击；治疗完成后回巡航 |
| 无可用悬停点／路径中断 | 有界重选或收纳等待，不在墙里永久停留；恢复期间不攻击、不隔墙治疗 |
| 正常缩放、亮度、低洞与开阔场景 | 可辨四旋翼、可辨停火与当前活动；常规巡航在镜头安全区域，有条件冲突时有提示 |
| 停火读档、丢弃／拾回／补领控制器 | 持久状态与画面一致；行为原因可见；不重复生成无人机和控制器 |
| 真实 F6/F7/F8、背包使用、设置／输入界面 | 和原版动作无冲突，输入界面不误触发；保存退出后仍能正常使用 |
| 原生 AI、守卫／炮塔等新增类别 | 对真实敌对对象实际命中，仇恨响应有记录；不主动攻击中立目标 |

3 秒、5 秒是下一版的初始验收目标，不是 0.1.0 已达到的成绩。每次实测保存输入指纹、步骤、截图和状态；反例必须保留，不能只选有利的空地场景。
