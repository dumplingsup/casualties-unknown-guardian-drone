# Guardian Drone 0.1.0 实现与验收

**后续复核：** 本文件保留当时的逻辑 smoke 证据。2026-11-15 的可玩性复测暴露了持续挡枪自伤、洞穴治疗不可达和脱困缺陷，可靠同伴体验结论为 FAIL。见 [可玩性复核与下一版方案](PLAYABILITY-REVIEW.md)；不要把下面的机制 PASS 当作总体体验通过。

日期：2026-11-15（Asia/Hong_Kong）。最新需求覆盖最初评估中的资源与友军保护建议：**初版无资源消耗、无人机无敌、远一点巡航、弹丸允许误伤，重画可识别的无人机外形**。验收时没有修改机甲源码，也没有把安装包写入正式游戏目录。

本文件随公开源码发布。隔离运行的日志、截图、存档和带游戏程序集的 stage 不在这个仓库里。下面的哈希和结论对应当时那一轮本地证据。

## 已实现

- 独立 `local.cu.guardiandrone` 插件，BepInEx + CUCoreLib；机甲是可选集成。
- 免费赠送控制器，使用／F6 部署和收回，F7 护航／停火，F8 优先医疗。支持随身容器中的控制器。
- 开阔空间默认约 6–9 格的上方弧线巡航；有限局部路径搜索、避障、持续卡住后的重新部署。医疗时靠近。
- 自动选择部分已知原版威胁；实际弹丸以 55 单位／秒飞行，扫掠碰撞防穿透。主角和旁人不会从碰撞中排除，墙体吸收弹丸，不挖地形。
- 单个生物肢体外伤止血、皮肤和肌肉修复。缺失肢体、义肢不走组织修复；有破片时不直接修复组织。严重外伤优先救治。
- 部署意愿、护航状态随角色存档；读取未来版本数据时禁用能力并保留原始数据。
- 原创 64×40 像素四旋翼，机身、桨叶、传感器、下挂工具分层。透明 PNG 与可重跑绘图脚本保留。参考与权利边界见 `pixel-art/guardian-drone/REFERENCES.md`。
- 机甲驾驶时使用可见机体位置作巡航参考、暂停对隐藏驾驶员的治疗；下机后恢复治疗。

## 隔离与方法

测试使用隔离的游戏副本和用户数据目录，未导入正式存档。这些目录不在本仓库中。测试副本仅对存储、PlayerPrefs 写入和成就接口做隔离：游戏 11 处路径重定向、28 处 PlayerPrefs 写入阻止、成就接口禁用；CUCoreLib 3 处路径重定向、6 处 PlayerPrefs 写入阻止。逐次启动前验证 unsafePaths/unsafePrefs/unsafeAchievements 全为 0。

正式用户数据目录现有的 `Player.log`、`Player-prev.log`、`settings.json` 哈希及文件集合前后保持一致。测试副本的修改版程序集和反编译资料不进入发布包。

本轮 Windows Computer Use 起初能选中并观察真实游戏窗口；随后 Esc 停止信号令该接口在当前执行中保持停止状态。用户明确要求继续后，剩余工作使用**独立测试插件**进行：调用正常物品 useAction、原生启动／读档／保存／换层、原生机甲部署／登机入口，并观测真实游戏对象、日志、截图和存档。地形、敌人和伤势由测试 fixture 准备。

这能证明运行中逻辑与实际状态变化，不能等同于玩家通过键鼠完成了背包菜单和快捷键验收。未通过 PowerShell 模拟键鼠或绕过停止的 UI 接口。测试插件不会打进玩家包。

## 实机证据

### 单独无人机：`runs/guardian-e-validation`

`assertions.json`、`telemetry.jsonl`、`results.jsonl` 与本轮截图：

| 用例 | 结果与证据 |
|---|---|
| 控制器与部署 | 角色控制器数量 1，部署无人机数量 1 |
| 远距跟随 | 移动 fixture 后，无人机与主人距离约 6.145 单位 |
| 自动攻击 | 11 发射击期间，原生 wallbiter 健康从 1000 降至 750；命中累计 10 |
| 墙体阻挡 | 在实际弹道中加入不透明碰撞墙后，目标健康在观察区间不再下降 |
| 误伤 | 日志出现 `PROJECTILE_BODY_HIT owner=True limb=头 damage=25`，实际主角受伤；全轮记录 5 次身体命中。未用随机直接扣血伪造误伤 |
| 外伤治疗 | 注入出血和组织伤后，出血降到 0，皮肤／肌肉逐步恢复；治疗时间和修复量累计增加 |
| 未来存档数据 | provider 的 version=99 与未知字段往返保留，再恢复原状态 |
| 暂停 | 稳定暂停后，无射击、无修复、组织状态不再变化 |
| 保存 | 原生 SaveGame 完成，隔离目录写入 save.sv；副本在本轮 `saved-checkpoint.sv` |

最初暂停断言在 PauseHandler 已变 true、原生 timescale 仍为 1 的过渡帧取样，组织自然恢复了约 0.011，导致失败；无人机修复和射击计数在该区间本来就没有增加。等待原生 timescale 稳定为 0 后重测通过，原始失败保留在 `assertions.json`，复测在 `assertions-pause-retest.json`，不覆盖历史。

### 最终 DLL 重启与机甲：`runs/guardian-final-reload-mech`

启动 PID 28184；与原运行分属不同游戏进程。加载上一轮原生存档，恢复 `deployed=true, guard=false`，控制器和无人机均为 1。

| 用例 | 结果与证据 |
|---|---|
| 完整退出后读档 | 部署和停火模式恢复，没有重复赠送／重复机体 |
| 机甲部署 | 调用现有信标的正常 useAction，完成原生空投／着陆／展开 |
| 登机巡航 | 原生 Enter 后，机甲 Pilot 与无人机 Piloting 同时成立，模式为 mech-escort |
| 驾驶时医疗 | 注入 bleed=8、skin=60、muscle=65，驾驶期间没有治疗，HealingSeconds 保持 16.8061 |
| 下机急救 | 原生 Exit 后，无人机靠近，约两秒出血由 8 降至 3.192，随后继续降至 0；治疗计数增长 |

`final-audit.json` 中 12 项证据与包哈希检查通过。初始审计曾把“正常控制器或登机调用已完成，但下一帧无人机尚未更新”的单帧观察当作失败；原始结果保留在 `final-audit-initial.json`。按 0.5 秒的有界状态稳定条件核对后通过，整个运行最大实例数始终为 1。此处没有通过改产品行为来掩盖失败。

## 分层结论与限制

| 门禁 | 状态 |
|---|---|
| STATIC | PASS：当前签名、嵌入资源、语言 JSON、像素硬透明、包文件集合与哈希核对 |
| BUILD | PASS：锁定 restore，Release 零错误零警告 |
| STAGE | PASS：单独与机甲两组合均校验通过 |
| BOOT | PASS：实际加载 CUCoreLib、Guardian，组合运行还加载 Wayfarer |
| GAMEPLAY（逻辑集成） | PASS：真实对象上的巡航、射击、误伤、治疗、墙体与暂停验证 |
| GAMEPLAY（键鼠与背包 UI） | NOT_RUN：当前 Computer Use 接口停止状态，未完成真实按键／菜单复验 |
| SAVE_RELOAD | PASS：独立进程重启恢复部署和停火；没有将下一层原版保存误称成同场景回溯 |
| COMPATIBILITY（Wayfarer 0.4.9） | PASS，仅限上述单人加载、登机巡航、医疗切换和换层路径 |
| COMPATIBILITY（多人／其他第三方组合） | NOT_RUN |
| 全敌人／全角色／复杂洞穴／规模性能 | NOT_RUN；不要从一个目标或本轮局部跟随推断全覆盖 |
| 美术 | 已查看源像素预览和真实游戏截图，最终外观由用户验收 |

隔离游戏日志保留了 `Failed to initialize Steam!` 和 CUCoreLib 查找 `Wearable.CreateSprites(Body)` 的警告；两种最终组合均存在。本轮没有 Guardian 异常堆栈。Steam 成就与线上行为不在测试范围内，不能以加载成功宣称库的所有功能均兼容。
