日期：2026-11-16（Asia/Hong_Kong）。结论：**可按 Windows 单人 Beta 准备发布**。这不是全敌人、全部模组组合、多人或长期稳定性验收，也不表示 Nexus 已上传、完成扫描或公开。

## 环境与证据

游戏 Steam build `26666273`、原版主程序集 SHA-256 `48c7f2296fc4a659faae3b1822884ca5b7ff73d6767ef159e6a6c2bc0b2d38f1`，与原基线一致。BepInEx 5.4.23.6、CUCoreLib 1.1；单独无人机组合，不加载机甲。

本地原始证据留在工具工作区 `runs/guardian-nexus-20261116`，不随公开源码分发。包括 `inputs.json`、profile/lock、`acceptance.json`、进程 PID、遥测、日志、截图和测试用 checkpoint。组合 stage 验证了 24 个文件，并锁定 12 个游戏输入指纹。

实机为隔离副本；路径、PlayerPrefs 与成就隔离复核均无 unsafe 项。副屏 1280×720 窗口、静音。真实 UI 与按键使用 Computer Use 的 `@oai/sky`；伤势、地形与测试敌人使用独立白名单探针。探针没有进入玩家包。原版 DLL 与 CUCoreLib 在测试副本中的路径隔离改动单独记录，未分发。

## 保留的失败与测试修正

原始 `no-hover-stows` 为 FAIL，记录没有删除。原因是旧夹具只封住主人周围，上方 8 格巡航点依然可达，无人机可正常停留；不满足“没有落点”的前提。修正版封住全部候选点，并仅在夹具内忽略封堵物与主人身体的碰撞，验证主人没被推走后重测通过。这个探针改动只用于验收。

一次测试重启读取到了上一进程遗留的 quit 命令而提前退出；另一次启动器隐藏了窗口。分别归档旧请求并按已授权的副屏可见窗口重启，原日志和进程记录保留。这些启动尝试没有记作读档通过。真正的 SAVE_RELOAD 证据来自可见窗口中点击“继续探险”后的第二次完整游戏进程。

日志仍有隔离环境的 Steam 初始化失败、CUCoreLib 查找 `Wearable.CreateSprites(Body)` 的已有警告，以及 Unity 的内存／vsync 诊断。本轮未发现 Guardian 异常堆栈；不能据此声称日志全无警告或性能已经通过。

## 上架必须写清楚的范围

- 单人 Beta；只核对 Windows x64 和上述 build，不声明其他版本或平台兼容。
- 当前索敌主要依赖类型、距离和部分地形视线，可能提前开战；不是完整敌意／仇恨识别。
- 只处理外伤出血、已有生物肢体的皮肤／肌肉。不能补血、治内伤、骨折、感染或再生断肢。
- HUD 可能与左上角原版物品标签重叠，较小窗口下尤其明显。
- 本轮静音，音效存在不等于听感／可听性通过。
- 未单独覆盖背包 Use 点击、0.1.0 → 0.2.0 存档升级、多人与第三方高风险组合、所有敌人、长时性能。
- 公开源码不等于授予开源许可证；页面按实际 AI 使用披露。没有替作者选择额外开放许可。
