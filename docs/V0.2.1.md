# Guardian Drone 0.2.1 修复记录

日期：2026-11-18。对应 Nexus 0.2.0 页面上的两条 Bug 报告（Ondra52011，2026-11-17）。GitHub Release v0.2.1 已发布（附件 `GuardianDrone-0.2.1.zip`）；Nexus 更新材料已准备，由作者在网页手动提交，本记录不声称 Nexus 已更新。0.2.0 的 ZIP、哈希和标签不改。

## 两条报告

1. **重复控制器**：使用允许随时存档的模组（报告链接到 `scavprototype/mods/7`，即 **QoL Unknown 7**）后，守护无人机模组会在玩家已经拥有控制器时再发一台。玩家要求检查控制器是不是放在储物物品里，或者放在快捷栏。
2. **换层卡死**：无人机处于部署状态时下到下一层，游戏会卡住不响应。玩家要求无人机在换层时自动收回，并锁定到下一层完全加载为止。

## 原因与改动

### 1. 控制器重复

0.2.0 每 0.4 秒用 `FindObjectsOfType<Item>()` 统计控制器。该接口只返回**激活中**的对象；发放前也只在一个短暂窗口内检查一次。随时存档类模组会在读档后逐步还原整层，包括储物箱里的物品；在这段时间里控制器可能暂时不在已激活的场景里，3 秒的补发计时就会先跑完，等原控制器被还原后背包里就有两只。

现在的判定：

- 先扫描角色层级（快捷栏、穿戴、容器里嵌套的物品），再扫描 `Item.allItems`（含容器内容），最后才用 `FindObjectsOfType<Item>(true)` 兜底扫描未激活的场景对象。`DontDestroyOnLoad` 里的自定义物品模板不算。
- QoL Unknown 7 的深度存档在还原自定义物品时直接实例化 CUCoreLib 的**未激活模板**，不会调用激活逻辑；原控制器会以不可见、不可拾取的状态留在场景里。0.2.0 的激活对象扫描看不到它，于是补发第二只。0.2.1 在兜底扫描里找到这种控制器时会把它 **激活**（日志 `CONTROLLER_ACTIVATED`），既保留原物品，也不补发；如果只统计不激活，玩家就会变成没有可用控制器。
- `DroneSave` 新增 `hadController` 持久字段。0.2.0 的旧存档没有这个字段，但 `deployed=true` 已能证明当时确实有控制器，读入时按已有处理。
- 读档后 12 秒内不发放任何控制器，给存档模组留出还原储物箱的时间；发放前再完整扫描一次。
- 如果补发的控制器先出现、原控制器随后才被还原，模组会**销毁自己补发的那一只**，保留玩家原有的；已有重复不会去删。
- 两次发放之间至少间隔 20 秒，避免来回补发。

### 2. 换层卡死与锁定

0.2.0 在换层时不清理无人机。旧无人机活过 `RegenerateWorld`，在新层重新生成期间继续按旧坐标导航；同时换层前确认面板没有拦截部署。诊断显示这不是一个永久的死循环，但旧无人机在未完成的世界里做路径搜索，会拉长本就很重的世界生成卡顿；玩家看到的就是不响应。

现在：

- 到达下层确认面板（`WorldGeneration.savePanel` 激活）时立即收回无人机；`doingRegen`、`generatingWorld`、尚未就绪、层号变化、存档还原序列变化，也都会触发同样的收回。
- 收回期间销毁无人机和飞行中的弹丸，`F6`／控制器使用被拒绝，HUD 显示「换层加载中」。
- 新层 `Ready` 之后再等 2.5 秒才解锁；解锁后如果 `deployed` 仍为 true，就在主人附近重新部署一台。部署意愿本身不改。
- 控制器统计改用 `Item.allItems`，不再每 0.4 秒遍历所有 Item，减少了换层后的额外开销。

版本号、插件版本和日志都升到 0.2.1；GUID、控制器 ID 和存档键不变，0.2.0 存档可以直接读。

## 实测

使用隔离副本 `furry/.local/cu-test/drone-game`（BepInEx 5.4.23.6、CUCoreLib 1.1）和只在该目录启用的 DroneProbe。原始 `bugfix.json`、`status.json`、`Player.log` 留在本地 `furry/runs/guardian-v021-bugfix2`、`furry/runs/guardian-v021-descent`、`furry/runs/guardian-v021-saveanywhere3`、`guardian-v021-saveanywhere4`、`guardian-v021-saveanywhere7`，以及下面的 QoL 实测目录，不随仓库分发。

2026-11-18 又在隔离副本里安装了**真实的 Save Anywhere 1.5.0**（Nexus 885，游戏 1.0.2）复测。为了让测试不碰正式用户目录，只对隔离副本里的 SaveAnywhere.dll 做了测试专用的路径重定向（1 处 `Application.persistentDataPath`）和 PlayerPrefs 写入 stub（4 处）；分发包和 Nexus 原 ZIP 没有改。测试前后 `%USERPROFILE%\AppData\LocalLow\Orsoniks\CasualtiesUnknown` 的 `Player.log`、`Player-prev.log`、`settings.json` 哈希一致。

| 场景 | 结果 | 证据 |
|---|---|---|
| 新局首次发放 | PASS | 控制器 1、世界 0、`hadController=true` |
| 部署 | PASS | `droneCount` 0 → 1 |
| 控制器放进世界储物箱 | PASS | 背包 0、世界 1、无人机收回，6 秒内没有第二只 |
| 关闭储物箱（未激活）6 秒 | PASS | 总数始终 1，没有补发 |
| 取回控制器 | PASS | 控制器 1、世界 0、无人机 1 台 |
| 控制器真实销毁后补发 | PASS | 约 3 秒后背包 1、总数 1 |
| 补发后原控制器又出现 | PASS | 补发的那只被移除，总数仍为 1，重新拾取后无人机 1 台 |
| 原生 `RegenerateWorld` 换层 | PASS | 换层期间 `droneCount=0`，`ready` 恢复并等待后重新部署 1 台；状态文件持续更新，无长时间停顿 |
| 真实确认面板 → Continue 换层（0 → 1） | PASS | 面板出现即 `transitioning=true`、`droneCount=0`；加载期间始终 0；完成后 1 台、控制器 1 |
| 保存 → 退出 → 读档 | PASS | 控制器 1、`deployed=true`，读档后重新部署 1 台，稳定后总数仍 1 |
| 读取 0.2.0 旧存档 | PASS | `hadController` 自动推为 true，控制器 1、停火状态恢复、无人机 1 台，22 秒内无重复 |
| 空手接弹道 / 治疗 / 换位 | NOT_RUN（本版） | 逻辑未改；0.2.0 的验收记录仍有效 |

换层实测里，状态文件在重生成阶段出现约 4 秒的停顿。这段时间无人机已经被销毁（所有采样 `droneCount=0`），停顿来自游戏自身的世界生成，不是本模组新增的路径搜索。报告中的永久卡死没有复现。

### QoL Unknown 7 v1.1.4 实测

2026-11-18 还安装了报告链接的**真实 QoL Unknown 1.1.4**（Nexus 7）复测。测试副本同样只重定向了 `Application.persistentDataPath`（18 处）并把 PlayerPrefs 写入替换为 stub（120 处）；原始 ZIP 和分发包没有改。正式用户目录的哈希在测试前后一致。

| 场景 | 结果 | 证据 |
|---|---|---|
| 0.2.0 + QoL：控制器丢在地上，存档后读档 | 复现报告 | QoL 的 `qolWorld.items` 保存了控制器；读档后 QoL 把它还原成**未激活**的自定义物品，0.2.0 记录 `CONTROLLER_GRANTED`；身上 1 只、场景里另有 1 只未激活，`allControllers=2` |
| 0.2.1 + QoL：同一条存档读档 | PASS | 深度扫描找到未激活的原控制器并激活（`CONTROLLER_ACTIVATED`），没有补发；拾取后 1 只控制器、1 台无人机，15 秒后仍为 1/1 |
| 0.2.1 + QoL：部署状态下从确认面板下层（0→1） | PASS | 面板出现即收回（`droneCount=0`），加载期间始终 0 台，完成后 1 台；QoL 的过渡写盘完成，状态文件最大间隔 0.23 秒，没有卡死 |

只统计、不激活未激活的还原物品时，会出现“没有补发但玩家也没有可用控制器”的状态；上面的 PASS 结果要求有 `CONTROLLER_ACTIVATED` 并把原控制器交回玩家。证据目录：`furry/runs/guardian-v020-qol1`、`guardian-v020-qol2`（0.2.0 复现）、`guardian-v021-qol3`（修复）和 `guardian-v021-qol5`（换层）。

## 仍未覆盖

- QoL Unknown 的槽位保存／自动存档 UI 没有逐个点击；测试走的是与它相同的 `SaveSystem.SaveGame` + `qolWorld` 保存路径，加载也走同一个 `TryLoadGame`。
- 多人、守卫／炮塔类敌人、机甲同场（本版没有改这些路径，也没有重跑）。
- 从确认面板选择「保存并退出」的完整 UI 流程；测试里通过面板锁定和 `ContinueRun`／`bottom-continue` 覆盖了继续下层的路径。
